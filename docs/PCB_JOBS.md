# Печатные платы из Gerber

Штатный плагин `io.millo.pcb-fabrication` включён по умолчанию и открывается
через `Создать -> Плата из Gerber`. Он собирает несколько производственных
слоёв в одно задание, но парсинг, геометрические операции и выпуск G-code
выполняет отдельное Rust-ядро `millo-pcb`.

## Поддерживаемый поток

1. Перетащите файлы из EasyEDA, KiCad или другой CAM-системы в окно плагина.
2. Millo определит роль по расширению. При необходимости измените её в строке
   файла: `Медь`, `Сверловка`, `Контур` или `Маркировка`.
3. Проверьте 2D-preview. Плату можно перетащить мышью, повернуть на 90 градусов,
   отразить по X и точно разместить числовыми X/Y.
4. Включите нужные операции и выберите инструменты из общей библиотеки.
5. Нажмите `Создать G-code`, затем сохраните `.nc` или откройте его в задании.
6. Дальше работают обычные preview, карта высот, GRBL Check, readiness,
   подтверждение физической установки и sender Millo.

Принимаются Gerber RS-274X (`.gbr`, `.gtl`, `.gbl`, `.gko`, `.gm1`, `.gml`,
`.gto`, `.gbo`, `.art`) и Excellon (`.drl`, `.xln`, `.txt`). Содержимое
разбирается по формату, расширение используется только для первоначального
выбора роли.

Устаревшие команды абсолютных координат `G90*` и метрического режима
`G71D02*`, которые всё ещё добавляет часть экспортов EasyEDA, безопасно
нормализуются перед разбором.
Инкрементальный `G91*` не принимается: такой файл нужно повторно экспортировать
в абсолютных координатах.

## Операции и инструменты

Операции выполняются в фиксированном безопасном порядке:

1. **Изоляция дорожек.** Ядро объединяет медные полигоны и строит один или
   несколько внешних offset-контуров с учётом радиуса инструмента и зазора.
2. **Сверловка.** Excellon-группы сохраняют исходные `T` и диаметры. Для каждой
   группы выбирается отдельное сверло или совместимый инструмент.
3. **Маркировка.** Опциональный Gerber-слой гравируется отдельным инструментом.
4. **Вырезание платы.** Контур компенсируется наружу на радиус фрезы, режется
   несколькими глубинами и оставляет равномерно распределённые перемычки.

При смене фактического `toolId` генератор добавляет `Tn M6`. Sender поднимает
штатный tool-change barrier и продолжает только после замены инструмента и
подтверждения оператора. Повторное использование того же инструмента не создаёт
лишнюю остановку. Подачи XY/Z берутся из Rust-библиотеки, а не передаются
плагином как произвольная геометрия.

Тип `Сверло` доступен в библиотеке инструментов. Для Excellon нужно создать
запись с фактическим диаметром, хвостовиком и подачей Z. Millo показывает
диаметр из файла рядом с каждым `T`, чтобы несоответствие было видно до расчёта.

## Что гарантирует ядро

- максимум 16 файлов и 12 MiB декодированного входа;
- максимум 200 000 точек preview и общий лимит G-code `millo-gcode`;
- миллиметровая геометрия с точностью 0,001 мм внутри Clipper2;
- union/difference для тёмной и очищающей полярности;
- базовые круглые, прямоугольные, овальные и многоугольные апертуры, регионы,
  вспышки, линейные и multi-quadrant дуговые интерполяции;
- явные `G21 G90 G94 G17`, Safe Z, `M5/M9` и финальный `M30`;
- отсутствие `M3/M4`, probing, coolant-on, `G53` и изменения WCS;
- повторный parse выпущенного текста через `millo-gcode` до возврата в UI;
- проверку полноты Excellon mapping и совместимости типа инструмента с каждой
  операцией на Rust-границе.

Сложные Gerber aperture macros, incremental/single-quadrant координаты,
непустые LM/LR/LS и устаревшие image transforms, step-and-repeat, aperture
blocks и Excellon slots пока отклоняются. Восстановительные ошибки парсера и
ошибки boolean-геометрии тоже останавливают расчёт. Это сознательная
fail-closed граница: Millo не выдаёт приблизительную траекторию, если не может
доказуемо воспроизвести CAM-геометрию.

## Выбор библиотек

`pcb2gcode` и `libgerbv` полезны как поведенческие ориентиры, но добавляют GPL
и внешний executable или native system dependency. Millo не прячет такой
бинарник за UI. `millo-pcb` использует pure-Rust
`lib_gerber_edit`/`gerber_parser` для структуры форматов и permissive
`clipper2` для offset/boolean geometry; policy генерации остаётся в собственном
тестируемом crate.

Источники: [pcb2gcode](https://github.com/pcb2gcode/pcb2gcode),
[gerbv](https://gerbv.github.io/),
[gerber_parser](https://docs.rs/gerber-parser),
[lib_gerber_edit](https://github.com/nicolube/lib_gerber_edit),
[clipper2](https://github.com/tirithen/clipper2).

## Regression fixtures

`crates/millo-pcb/tests/fixtures` содержит собственные небольшие
EasyEDA-подобные слои меди, контура и Excellon с двумя инструментами. Тесты
проверяют inspect, rotation/mirror/offset, полноту drill mapping, три tool-change
barrier, перемычки, отсутствие запуска шпинделя и повторный parse программы.

```bash
cargo test -p millo-pcb
npm run test:ui -- --run src/plugins/pcb-fabrication
npm run verify
```
