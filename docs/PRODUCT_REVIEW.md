# Продуктовый разбор: 2026-09-05

Проверены структура workspace и зависимости, состав Rust-доменов, основные
пути command actor/sender, Tauri IPC, приложение и plugin host, рабочие экраны,
сохранение, наборы тестов и выпуск. Это не формальное доказательство отсутствия
дефектов в каждой строке и не аппаратная сертификация.

## Исправленные недостатки

| Проблема | Изменение | Регрессионная проверка |
| --- | --- | --- |
| Ответ snapshot мог приходить после нового event и откатывать UI; между чтением и подпиской терялось событие | Общий `bindSnapshotStream`: сначала listener, затем чтение; поздний результат не перекрывает event; cleanup при поздней регистрации | MachineStateEventStream и bindSnapshotStream tests |
| Частично frozen DTO и исключение подписчика | Полное клонирование/заморозка снимка, изоляция listener и его error reporter | MachineStateSource tests |
| Восстановление Z отменялось очередным равным WCO-объектом | `useProbeDatum`, примитивные зависимости, чтение и подписка surface session, явная привязка к профилю/WCS/reset/reconnect | probeDatumModel + stream regression tests |
| Ошибка WebGL могла разрушить рабочий экран | Границы ошибок сцены/задания/корня, отдельная recovery-оболочка и запись `ui.render_failed` | Browser fault injection без WebGL |
| Остановка была частью прокручиваемого пульта | Независимые постоянно смонтированные RealtimeControls в полосе состояния | Stable-slot render test; browser shell checks |
| Ошибка исчезала прежде, чем оператор успевал её прочитать | Постоянное уведомление рядом с рабочей областью, явное закрытие и переход в журнал | Ручная проверка оболочки; механизм без таймера |
| Рабочее место перегружено повторными статусами | Компактные координаты, навигация, большой preview, сворачиваемая диагностика | Desktop/compact/mobile workflow screenshots |
| Сохранение G-code могло оставить частично записанный файл | Parser в blocking task; synced временный файл и атомарная замена; уникальные temp-имена без JSON backup namespace | Storage tests: overwrite, failure, concurrent exports |
| Большие файлы смешивали разные обязанности | Отдельные `program_execution.rs`, `commands/program_io.rs`, workspace-компоненты, Z-datum hook | Существующие actor/IPC/domain tests без смены протокола |
| Не было исполняемого браузерного release gate | Playwright: запуск/пауза/остановка, Check, повтор, M6, справка, пиксели сцены, отказ WebGL | `npm run test:workflow`; macOS/Linux CI |

## Границы проверки

Локальный `npm run verify:product` успешно завершён: 295 TypeScript-тестов
в 81 файле, 428 Rust-тестов, 5 тестов сайта и 21 браузерный сценарий.
Production build, ограничения bundle size, architecture/security checks,
rustfmt и Clippy с `-D warnings` также прошли. Снимки сцены проверены на
1440x960, 860x600 и 390x844; исправлены выход селектора станка за header и
выход кнопок Jog за панель. Эти числа относятся к локальному прогону 2026-09-05.

Первый облачный прогон macOS прошёл; Linux выявил непереносимое ожидание
в тесте sparse-status карты высот: 2000 коротких пауз истекали раньше
завершения виртуального движения. Helper теперь ждёт событие с явным
30-секундным timeout и сразу показывает неожиданный terminal state.
Производственные таймауты и алгоритм движения при этом не менялись.

Существующие motion/authorization guards намеренно не ослаблены. Наличие
профиля, статус GRBL и автоматические тесты не доказывают физическое наличие
концевиков, аварийной кнопки, контакта щупа или правильно включённого шпинделя.
Новая оболочка не включает движение автоматически.

Браузерные сценарии используют **только development fixtures**, без serial.
Они доказывают переходы интерфейса, а не время реального торможения. Реальные
serial framing, recovery и planner проверяются отдельно Rust Mock/PTY-тестами.
Аппаратных перемещений в рамках этого разбора не выполнялось.

`FeatureErrorBoundary` ловит ошибки render/lifecycle, но не остановит зависший
JS thread и не гарантирует работу кнопок при крахе всего WebView/процесса.
Физическое отключение питания остаётся независимым средством остановки.

## Оставшийся долг

- `App`, `ProgramWorkspace`, native commands и actor dispatch всё ещё крупные.
  Извлечены самостоятельные обязанности, но тотальная миграция в один релиз
  создала бы дополнительный риск для уже работающей обработки.
- Новый layout использует существующие feature-стили. Остальные диалоги ещё
  не переведены на единый компонентный дизайн-контракт.
- Браузерная матрица Chromium не подменяет WebKit/macOS или WebKitGTK/Linux.
  Новый CI должен реально пройти; подпись/нотаризация не добавлены.
- В корне пока нет `LICENSE` и комплекта third-party notices. Лицензию
  проекта должен определить владелец; этот разбор не назначает её автоматически.
- Поддержка GRBL/Gerber ограничена парсером и fixture-корпусом. Формулировки
  «все диалекты», «все платы» и «безопасно в любых условиях» не применяются.
- Потеря питания без homing/достоверных координат не позволяет обещать точное
  продолжение с физически последней точки.

## Основания

### Аудит зависимостей

`cargo audit --json` (база RustSec от 2026-09-02) завершился без записей в
`vulnerabilities`, но с 17 предупреждениями `unmaintained` и одним `unsound`.
Среди них GTK3 bindings, proc-macro-error, smartstring, unic и
[RUSTSEC-2024-0429 для glib](https://rustsec.org/advisories/RUSTSEC-2024-0429.html).
Это не «чистый security audit»: применимость транзитивных Linux-путей требует
отдельной проверки, а обновление glib через другую несовместимую major-ветку
не является корректной локальной заменой зависимости Tauri.

Повторный `npm run test:dependencies` не завершился из-за `ETIMEDOUT` сервиса
advisories npm. Сетевой сбой не считается отсутствием уязвимостей. Основной
локальный тестовый gate не зависит от доступности этого сервиса.

Применены стандартные механизмы [React error boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)
и [Playwright projects/webServer](https://playwright.dev/docs/test-configuration).
Native UI имеет отдельные ограничения автоматизации:
[Tauri testing](https://v2.tauri.app/develop/tests/).
Архитектурные правила проекта описаны в [ARCHITECTURE.md](ARCHITECTURE.md),
расширения — в [PLUGIN_DEVELOPMENT.md](PLUGIN_DEVELOPMENT.md).
