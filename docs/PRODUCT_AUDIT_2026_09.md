# Продуктовый аудит: сентябрь 2026

## Цель и границы

Millo предназначен для подготовки и выполнения фрезерования, гравировки,
сверления и раскроя на GRBL. Архитектурная цель: одна программа от простого
чертежа/изображения/PCB до проверенного задания, без конкурирующих владельцев
контроллера. Это не универсальная промышленная CNC-система и не доказательство
отсутствия всех дефектов.

Аудит выполнен от `af3c5b7` в четырёх независимых направлениях: sender/controller,
CAM/карта высот, React operator flows, plugin host/parser/native boundaries.
Физические движения не выполнялись. Проблемы ниже относятся к проверенному
коду, а не к утверждениям о качестве автора или модели, написавшей его.

## Проверенные исправления

| Область | Дефект и решение | Регрессия |
| --- | --- | --- |
| Plugin lifecycle | Пока старый `deactivate` ожидает Promise, повторная загрузка того же ID запрещена. Повторная выгрузка ждёт ту же операцию; capabilities закрываются сразу | `InMemoryPluginLoader.test.tsx` |
| UI registry | Старый disposable больше не удаляет новый contribution с тем же ID; исключение observer не прерывает регистрацию/удаление | `ExtensionRegistry.test.ts` |
| Read models | Единая доставка подписчикам из снимка списка; удалённые подписчики пропускаются, новые получают следующее событие, исключения изолированы | `notifyListeners.test.ts`, store tests |
| Инструменты | Поздний ответ с меньшей/равной native revision не откатывает библиотеку. Снимки клонируются и полностью замораживаются; ошибочный listener не превращает сохранение в ложную ошибку | `ToolLibraryService.test.ts` |
| Привязка инструмента | Surfacing job запоминает ID инструмента до await, а не читает изменённый запрос после генерации | `JobCreationService.test.ts` |
| Парсер | Геометрия дуг выделена в `millo-gcode/geometry.rs`. Бюджет проверяется до выделения массивов; после исчерпания дальнейшая дискретизация прекращается, исходные строки сохраняются | `geometry_limits.rs`, 2000 чрезмерных дуг и общий бюджет |
| Границы | В дискретизацию дуг добавлены экстремумы X/Y/Z: размер preview не занижается из-за несовпадения равномерных отсчётов с вершиной дуги | Три плоскости G17/G18/G19 |
| Ошибочные блоки | Повторные value words не трактуются как «взять последнее». Непредставимые GRBL float-числа блокируются до расчёта | Duplicate word, overflow/underflow fixtures |
| Native CAM | Общий предел двух одновременных CPU-заданий вместо неограниченного `spawn_blocking`. Permit принадлежит worker, не отменяемому IPC caller; лишние запросы получают явную ошибку | `background_compute` cancellation/error/panic tests |
| Экспорт расширений | `.millo-plugin` заменяется атомарно через общий storage helper, без обнуления старого файла при начале записи | Общие atomic storage tests |
| Readiness | Наличие концевиков в профиле больше не означает, что станок базирован в текущей сессии | `millo-run` unreferenced/invalidated/failed fixtures |
| Resume | Ожидание свежего статуса учитывает ACK, стоящие перед ним в общем потоке; не теряет подтверждения буферизованных строк | Actor delayed ACK/resume fixtures |
| Конкурирующие запросы | Inspector, повторная подготовка запуска и изменение firmware settings не забирают ACK активного sender. Действия настройки на паузе допускаются только после освобождения очереди | Actor admission и paused ACK fixtures |
| Hold и M6 | Последний ACK не снимает паузу. Окно смены инструмента появляется после свежего Idle, не только после принятия строк контроллером | Sender + actor drain/barrier fixtures |
| Transport fault | У realtime write есть deadline. Ошибка Hold не отменяет независимую попытку Reset; disconnect активного задания сначала пытается остановить поток | Stalled/failing transport fixtures |
| Reconnect | Старые WCO, позиция и pending response не переносятся в новую сессию через sparse status | Controller recovery fixture |
| Homing timeout | Переполнение расчётного Duration не вызывает panic actor; применяется ограниченный watchdog | Обычные и экстремальные firmware settings |
| PCB-перемычки | Контур делится в точных границах перемычек с учётом диаметра фрезы, вместо определения по середине сегмента | PCB outline fixtures |
| Геометрия инструмента | Некорректные углы/диаметры блокируются; глубина не превышает рабочую длину в PCB, surfacing и sketch | Tooling/CAM workflow fixtures |
| SVG-кривые | Коллинеарная кривая, меняющая направление, не упрощается в одну хорду с потерей формы | Quadratic/cubic reversal fixtures |
| Карта высот | Сетка, spacing, привязка samples и конечность Z проверяются перед интерполяцией/расчётом качества; обрезанный файл даёт ошибку, не panic | Heightmap corruption fixtures |
| Async UI | Старые ответы после смены задания, профиля, параметров или закрытия диалога не заменяют новое состояние и не продолжают запуск | `program-lifecycle.spec.ts` |
| Координатор задания | Подписка на sender и согласование запоздалых ответов выделены в `useProgramSender`; порядок событий проверяется независимо от визуального layout | Completed Check / delayed reply browser fixture |
| Preview | Callback выбора не пересоздаёт WebGL renderer; после изменения геометрии восстанавливается инструмент. Буферы строятся сразу в typed arrays, строки индексируются один раз | Read-model tests, browser canvas/rotation checks |

Итоговая локальная проверка: **328 TypeScript-тестов, 483 Rust-теста,
5 тестов сайта и 120 браузерных сценариев прошли**. Последние выполняются
в Chromium desktop/compact/mobile и WebKit desktop/mobile; проверены canvas
pixels, переключение вида и отсутствие горизонтального переполнения.
Относительно исходного среза добавлены 15 unit-тестов TypeScript,
41 Rust-тест и 11 браузерных сценариев на каждой из пяти конфигураций.

Пройдены `npm test`, `npm run build`, `npm run lint:rust`,
`npm run test:workflow`, `npm run test:notices`; desktop-пакет дополнительно
перепроверен после финальной правки. Строгий Clippy сначала выявил лишний clone
в новом PCB-тесте: он удалён, повторная проверка прошла без подавления lint.
CI на Rust 1.98 дополнительно выявил запись массива байтов в тесте, которую
локальный Rust 1.96 не отмечал; запись нормализована без изменения поведения.
Начальный JS bundle 476.87 kB при лимите 500 KiB; Three.js остаётся lazy.

Новые ограничения не обходят Check, actor, Z datum,
одноразовое разрешение или ручную смену инструмента.

Arc radius checks сверены с GRBL 1.1: абсолютный допуск 0.005 мм,
далее ограничения 0.5 мм и 0.1% радиуса. Это устраняет как ложный отказ на
маленьких дугах, так и принятие дуги, которую firmware отвергнет.

`npm audit`: 0 известных vulnerabilities. `cargo audit`: 0 vulnerabilities,
17 `unmaintained` предупреждений, преимущественно GTK3/Tauri dependencies;
RustSec snapshot от 2026-09-02. Эти предупреждения не скрываются и не считаются
устранёнными. Предыдущий glib backport остаётся проверяемым vendor patch.

Сверка 6 сентября 2026: Candle stable
[v11.2](https://github.com/Denvi/Candle/releases/tag/v11.2), локальные исходники
Candle `b7ac8abd42245d5e8d3ed7c486b0c1e6536adacd`;
cncjs [README](https://github.com/cncjs/cncjs/blob/a025ab212882a628fbd122d1010a11c6c8f9c6ca/README.md).
Версии и файлы зафиксированы: документация master может измениться.

| Задача | Millo сейчас | Вывод |
| --- | --- | --- |
| GRBL serial sender, Hold/Reset, overrides, Check | Есть actor-owned lifecycle и регрессионные тесты | Основной продуктовый сценарий, но нужны повторяемые аппаратные замеры |
| Work zero, Z probe, heightmap | Есть единый surface session, сохранение и компенсация | Не доказывает физическое положение после отключения питания/пропуска шагов |
| Ручная M6 и повтор участка | Host barrier, восстановление modal state, отдельный Check и разрешение | Более строгий, не побайтово совместимый с произвольными скриптами Candle |
| Редактор и 3D preview | Есть подсветка, undo/redo, выбор строки/сегмента, инструмент | Очень большие файлы ограничены: 2 MiB, 200000 строк, 500000 preview points |
| Подготовка обработки | Изображение/SVG, Gerber/Excellon, выравнивание, 2D CAD/CAM с проектом | Отличительная возможность Millo; это не замена полноценному 3D CAM |
| Макросы/плагины | Встроенный React SDK и внешние bounded Rhai packages | Не равнозначно произвольным Qt/JS widgets; это осознанная граница доверия |
| Поворотная ось | A доступна в профильном Jog/telemetry | Полноценное выполнение четырёхосевой программы пока не поддержано parser/policy |
| Время обработки | Feed/dwell estimate с признаком неполноты | Не достигает planner/acceleration-aware оценки Candle |
| Сеть и SD | Основной транспорт serial/PTY | Нет пользовательских Telnet/WebSocket и FluidNC SD lifecycle |
| Другие прошивки и пульты | GRBL-first desktop | Нет Marlin/Smoothieware/TinyG/g2core, многоклиентного сервера, pendant API |
| Распространение | macOS arm64 DMG и Linux packages | Нет проверенного Windows-релиза и Apple notarization; лицензия проекта не выбрана |

Candle документирует сетевые подключения в
[v10.10](https://github.com/Denvi/Candle/releases/tag/v10.10.4), работу с SD в
[v10.12](https://github.com/Denvi/Candle/releases/tag/v10.12), сплайны в v11.2.
Не следует просто разрешать эти G-слова в GRBL 1.1 parser: возможности прошивки
должны подтверждаться отдельным dialect contract. Основание для обычных
GRBL-блоков: [официальный parser](https://github.com/gnea/grbl/blob/master/grbl/gcode.c).
Для архитектуры remote clients и дополнительных контроллеров см.
[cncjs introduction](https://cnc.js.org/docs/).

Подробное сравнение механизмов выполнения: [CANDLE_SENDER_COMPARISON](CANDLE_SENDER_COMPARISON.md).
Меньшее число разрешённых низкоуровневых операций нельзя выдавать за полную
совместимость, а наличие Rust само по себе не доказывает надёжность.

## Следующие критерии готовности

1. Полный machine-envelope preflight: фактический старт, активный WCS/WCO,
   перемещения между инструментами, дуги, safe Z, depth offset и heightmap.
   Сейчас captured envelope защищает continuous Jog, но не является полным
   доказательством размещения задания. Нужны отдельные fixtures для каждого
   преобразования и отрицательные аппаратные проверки без резания.
2. Файлы существенно больше текущих лимитов: потоковый parse/plan, независимый
   bounded preview и проверка на миллион строк с измерением памяти и latency
   Hold. Простое повышение констант не решает стоимость копий и IPC.
3. Firmware capability layer, затем network transport с heartbeat/разрывом,
   FluidNC/grblHAL fixtures, A-axis execution и поддержанные coolant blocks.
   Сетевой порт не должен создавать второго writer или обходить session fences.
4. Отдельный кинематический estimator с rapid, acceleration и junction limits.
   Критерий: сравнение с измеренным временем и явно показанная погрешность.
5. Поддерживаемые релизы/миграции: однозначный immutable release, Linux/Windows
   native smoke, Developer ID/notarization, решение владельца о лицензии.
6. Аппаратная приёмка типовых сценариев: pause/resume, M6/Z повторная привязка,
   probe miss/resume, reconnect, USB-питание без питания двигателей, полное
   отключение ПК. Автотесты не заменяют проверку реальной электрики и кинематики.

Остаточные UI-оптимизации: `HeightmapScene` пока перестраивает геометрию при
обновлении карты; определение текущего номера инструмента читает предшествующие
строки. Это отдельные задачи на incremental buffers/modal index, а не основание
менять рабочую систему координат или ослаблять проверки запуска.

Эти пункты остаются открытыми. Аудит улучшает текущий рабочий продукт, но не
объявляет Millo превосходящим всех конкурентов по всем параметрам.
