# Millo: продуктовое назначение

Millo — рабочее приложение оператора небольшого GRBL-станка: подготовить
траекторию, привязать её к заготовке, проверить, выполнить и разобраться с
прерыванием. Основной сценарий — один оператор и один подключённый контроллер.
Не CAD общего назначения, не промышленная система функциональной безопасности
и не автоматическая компенсация любых ошибок механики.

## Рабочее место

- Верхняя полоса: состояние, рабочие координаты, щуп, рабочий ноль, Hold/Reset.
- Левая навигация: задание, станок, инструменты, поверхность, журнал, справка,
  настройки. Переход к Inspector не выгружает текущее задание.
- Центр: траектория и подготовка/выполнение одного задания.
- Правая панель: подключение и ручное управление. Диагностика раскрывается
  по требованию. Координаты и остановка не зависят от прокрутки Jog.
- Ошибка действия остаётся видимой до закрытия оператором; подробности доступны
  в журнале. Справка работает локально, без подключения к интернету.

## Сценарии и инварианты

| Сценарий | Ожидаемый результат | Что не должно происходить |
| --- | --- | --- |
| Загрузка/генерация | Обычный G-code, parse, preview | Самопроизвольное движение |
| Подготовка | Один следующий шаг рядом с заданием | Непонятная блокировка без причины |
| Z найден щупом | Привязка сохраняется при установке XY | Повторное обнуление Z по текущей высоте |
| Карта высот | Явное применение к проверенной привязке | Применение чужой/устаревшей карты |
| GRBL Check | Возврат к подготовке после успеха | Экран Completed без следующего действия |
| Запуск | Проверенный файл, новая авторизация, подтверждение оператора | Использование старой авторизации |
| Пауза | Продолжить либо остановить задание | Jog поверх активного sender |
| M6 | Видимый ожидаемый инструмент и подтверждение | Тихое ожидание или отправка M6 напрямую |
| Завершение | Возврат к нулю/повторный запуск | Восстановление уже законченного задания |
| Потеря связи/питания | Сохранение свидетельств, явная процедура восстановления | Автоматический старт после reconnect |
| Ошибка сцены | Локальная панель ошибки, остальная оболочка жива | Потеря всей рабочей области из-за WebGL |

Проверка движения физически двигает станок без инструмента. GRBL Check не
двигает оси. Обработка включает гравировку, фрезерование и сверление, но только
в рамках поддерживаемого диалекта и настроенного оборудования.

## Архитектурное решение

Сохраняется модульный монолит: Rust-домены, один владелец serial, типизированные
use cases, Tauri-адаптер и React-представление. Переход на микросервисы или
переписывание sender не решает текущие проблемы операторского сценария.
Плагины используют те же CAM и machine capabilities; второй канал записи в
контроллер не появляется даже в экспертном режиме.

## Критерии релиза

`npm run verify:product` объединяет доменные, компонентные и браузерные проверки.
Browser fixtures проверяют UI, а Rust Mock/PTY проверяют протокол. Это разные
свидетельства; ни одно не доказывает физическую безопасность конкретного станка.

Статус остаётся **alpha** до выполнения отдельной аппаратной матрицы:
реальная пауза/сброс, снятие и повторное применение карты, смена инструмента,
потеря USB и питания, длительное задание, восстановление с подтверждёнными
координатами. Нужны также подписанные/нотарифицированные macOS-пакеты,
проверка Linux-пакетов на чистой системе и проверка установленного native UI.
Новый CI не равнозначен уже полученному успешному результату на всех платформах.

Следующее развитие: измеряемая задержка остановки под нагрузкой, native GUI
интеграционные тесты с внешним PTY, унификация оставшихся диалогов и стилей,
постепенное уменьшение `App`, `ProgramWorkspace` и actor dispatch без изменения
владения портом. Перечень текущих изменений: [PRODUCT_REVIEW.md](PRODUCT_REVIEW.md).
